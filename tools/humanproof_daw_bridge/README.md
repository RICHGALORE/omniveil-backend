# HumanProof DAW AutoDetect v1

Privacy-first macOS companion for automatically attaching DAW creation evidence to HumanProof.

## What it detects

The bridge does **not** trust a typed DAW name. It looks for a running audio application with an actually-open project file.

Built-in DAW profiles include Logic Pro, Ableton Live, Pro Tools, FL Studio, Studio One, Cubase, Nuendo, REAPER, Bitwig Studio, GarageBand, Adobe Audition, Reason, Ardour, Renoise, LMMS, Cakewalk, Tracktion Waveform, and Samplitude / Sequoia.

An unknown foreground DAW can also be detected automatically when its project extension is supplied in `custom_project_extensions`. Adding a DAW is therefore data/configuration, not a new integration architecture.

## Automatic evidence flow

1. Detect running DAW + open project.
2. Start or resume a recording HumanProof session.
3. Hash the project locally and append `source_captured`.
4. Watch for stable project changes, debounce noisy writes, re-hash locally, and append `work_saved`.
5. Watch approved export roots plus the project directory for stable WAV/AIFF/MP3/M4A/FLAC files and append `work_exported` with the export SHA-256.
6. If the DAW closes, leave the HumanProof session open so the creator can still complete AI disclosure, registration, asset binding, and sealing in HumanProof Studio.

## Privacy boundary

The bridge never uploads the DAW project or its local filesystem path. HumanProof receives only evidence metadata such as:

- detected DAW name
- project filename/extension
- privacy-safe SHA-256 token of the local project path
- project content fingerprint
- file count / byte count
- export filename / size / SHA-256
- timestamps generated by the HumanProof API

The API key is read from the environment and is not stored in the bridge state file.

## macOS requirements

- macOS
- Python 3.11+
- built-in `ps`, `lsof`, and `osascript`
- permission for Terminal/Python to inspect the user's own running applications. macOS may prompt for Automation permission when `System Events` is queried for the foreground app.

## Configure

Optional configuration lives at:

```text
~/.omniveil/daw-bridge.json
```

Copy `config.example.json` and limit `export_roots` to folders the creator approves. The default is `~/Music`.

Required environment variables:

```bash
export OMNIVEIL_API_URL="https://your-omniveil-backend.example"
export OMNIVEIL_API_KEY="<tenant-api-key>"
export OMNIVEIL_CREATOR_ID="creator-local-id"
```

`OMNIVEIL_CREATOR_ID` defaults to `humanproof-daw-bridge` when omitted. It is an internal event identifier, not a legal authorship conclusion.

## Run

From the backend repository root:

```bash
python -m tools.humanproof_daw_bridge.bridge
```

Expected output:

```text
[HumanProof DAW] AutoDetect running. No project content is uploaded by the bridge.
[HumanProof DAW] Started HP-...: Logic Pro · Turn Me Up.logicx
[HumanProof DAW] Captured project fingerprint 0d81e4a7c210…
[HumanProof DAW] Project revision recorded c7fbdf20c681…
[HumanProof DAW] Export recorded: Turn Me Up Master.wav · c29fa74f38d1…
```

## Important scope

This is DAW AutoDetect **v1**. It detects process/project/file evidence without injecting into the DAW or reading creative content semantically. Richer transport/tempo/track events can be added later through DAW-specific adapters, but the core HumanProof evidence chain does not depend on those adapters.
